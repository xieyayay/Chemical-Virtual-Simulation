
## 修复 .gitattributes 的 LFS 规则失效
- 现象：配置了 LFS 仍提示文件太大。GitHub 单文件硬限 100MB，超限文件 `aa 5.7/Content/Anim_character/NewMetaHumanCharacter.uasset`（120.8MB）被当普通 blob 提交。
- 两个根因：
  1. `.gitattributes` 在 `aa 5.7/` 子目录内，规则相对该目录解析，原来写了 `aa 5.7/Content/...` 前缀 → 实际解析成 `aa 5.7/aa 5.7/Content/...`，永不命中。
  2. 路径含空格未加引号 → git 只取 `aa` 当模式，`5.7/Content/MetaHumans/**` 被当属性名，报 `is not a valid attribute name`。
- 修复：改为 `Content/Anim_character/** filter=lfs diff=lfs merge=lfs -text`；MetaHumans 那行注释掉（571 个文件 2.3GB 已按普通 blob 推送成功，全量转 LFS 会超 GitHub 免费 1GB 配额）。根 `.gitattributes` 加 `.gitattributes text eol=lf` 防 CRLF 破坏匹配。
- 验证：`git cat-file -s` 显示索引中仅 134 字节指针；`git rev-list --objects origin/HEAD..HEAD | git cat-file --batch-check` 审计无 >100MB blob；`git lfs status` 仅 1 个待上传对象。
- 结论：以后加 LFS 规则必须在 `.gitattributes` 所在目录的相对路径上写，空格路径用双引号；转换已完成提交的历史文件需 `git lfs migrate import`，且先确认 LFS 配额。
