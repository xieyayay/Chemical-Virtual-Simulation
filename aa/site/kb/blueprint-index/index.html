    蓝图知识点总表¶

    137 条，9 个模块。这份表只负责「不重不漏地列出来」——正文由你自己写。

    状态：草稿　最后核对：2026-11-20　适用版本：UE 5.7.4

    一、先诊断：为什么归纳不出来¶

    不是你想不出来，是方法用错了。三个典型症状，对号入座：

    症状 你实际在做的事 为什么必然失败
    想到哪写到哪，写了一堆又觉得漏了 按「记忆顺序」归纳 记忆是无序的，永远无法证明「写完了」
    每个概念都写得很长，写三条就累 粒度失控 「蓝图通信」和「Branch 节点」被放在同一层，一个要 3000 字，一个只要 3 行
    抄了一遍教程目录，还是不会用 借别人的切法 教程按「功能」切（变量/函数/流程），你要按「接手项目」切（对象/通信/生命周期），切法不匹配，学了也串不起来

    解法只有一句：不要凭记忆列，用维度矩阵扫。矩阵扫出来的空格，就是你的漏项。

    二、三个工具¶

    工具 1 · 正交切分（六个维度）¶

    任何「一套技术」都能被六个正交维度切开。蓝图对应的六个维度：

    维度 问的问题 落到蓝图是什么
    本体 它是什么？编译成什么？ 蓝图是可视化脚本 → 编译成字节码 → 生成 GeneratedClass 与 CDO
    形态 它以哪些资产形式存在？ Blueprint Class / Interface / Macro Library / Function Library / Enum / Struct / DataTable / Widget / AnimBP / LevelBP
    语法 写它的时候有哪些语法单元？ 变量 / 函数 / 宏 / 事件 / 节点 / 委托 / 注释
    结构 它在运行时构成什么？ Actor / Component / 层级 / 碰撞 / Transform
    时间 它什么时候执行？活多久？ 编译 → 构造 → BeginPlay → Tick → EndPlay → 销毁；换关
    协作 它怎么和别人说话？怎么被调试？ 引用 / Cast / 接口 / 委托 / 子系统；断点 / 日志 / Stat

    校验法：六个维度里，每个维度都必须能回答「这个维度上有哪些条目」。哪个维度你答不满，就是那块没学透，不是「不知道写什么」。

    工具 2 · 粒度尺（判断一条该不该独立成条）¶

    一条知识点必须同时满足：

    1. 15 分钟能讲清并验证（讲不清＝该拆；3 分钟讲完＝该并到上一条）
    2. 能出一道自测题（出不了题＝这条没有可检验的内核，是空话）
    3. 在项目里能找到锚点，或者能明确说「本项目不用，因为___」

    用这把尺子量，「蓝图通信」太大（要拆成 5 条），「Branch 节点怎么连」太小（并进「流程控制节点」）。

    工具 3 · 漏项矩阵（三个必扫矩阵）¶

    矩阵 A · 资产类型 × 四态

    创建 编辑 被引用 删除/迁移
    Blueprint Class 新建蓝图选父类 事件图/组件/默认值 Cast/引用/生成 引用查看器
    Blueprint Interface 新建接口 只声明函数 实现/消息 实现方全改
    DataTable 导入 CSV / 手填 行结构来自 Struct 按 RowName 查 行被引用会断
    Widget Blueprint 新建控件 层级/绑定/动画 Create Widget 父控件删了会崩

    扫这张表，你会发现「删除一个 DataTable 行会断什么」这种问题，光看教程永远想不到。

    矩阵 B · 语法单元 × 四问

    怎么声明 怎么赋值/调用 谁来触发 怎么调试
    变量 左侧面板 Set 节点 任何图 观察值
    函数 函数图 Call 节点 任何图 断点进栈
    宏 宏图 宏节点 任何图 只能断外面
    事件 事件节点 —— 引擎/自定义 断点
    委托 Dispatcher Bind / Call 广播方 断点看绑定数

    矩阵 C · 协作方式 × 三评

    方式 优点 代价 失败模式
    直接引用 最快 强耦合 引用为空 → 静默失败
    Cast 类型安全 必须知道目标类 Cast 失败 → 什么都不发生，不报错
    接口 解耦 调试链路长 忘了实现 → 消息被吞
    Event Dispatcher 一对多 生命周期要管 对象销毁后仍绑定 → 崩溃
    子系统 全局可达 隐蔽依赖 到处取，谁改了什么说不清

    这三个矩阵扫完，你的清单就在结构上完备了。

    四、从知识到项目：三条串联线¶

    知识点列完只是「散装」。串联靠三条线，每条线最后都能自然过渡到项目讲解：

    线 1 · 一次调用的数据流（讲「怎么动」）¶

    输入（玩家按键）
  → 意图（Enhanced Input / 旧 Axis）
  → 入口（Controller 还是 Character 接收）
  → 判定（Trace / Overlap / 距离）
  → 分发（Cast / 接口 / 委托）
  → 处理（改自身状态 / 播动画 / 改数据）
  → 反馈（UI / 音效 / 特效）
  → 持久化（GameInstance / SaveGame / DataTable 记录）

    对应知识点：B2-17/18、B3-15/16、B4-01~07、B6-09。

    讲项目时：拿「按 E 拿镊子」走一遍这条线，每个箭头停一下，说清「这一步由哪个知识点负责、代码在哪」。

    线 2 · 一个对象的生命周期（讲「活多久、谁先谁后」）¶

    类定义（CDO：默认值）
  → 实例化（关卡摆放 / Spawn）
  → 构造脚本（编辑器期）
  → BeginPlay（进世界）
  → Tick / 事件驱动（运行期）
  → EndPlay（销毁 / 换关 / 退出）
  → 引用清理（定时器、委托、缓存）

    对应知识点：B0-03/05、B3-05/06、B5-01~12。

    讲项目时：拿 BP_TaskManager1 走一遍，重点讲「换关时它没了，所以状态必须放 GameInstance」——这是理解框架五件套最快的一条路。

    线 3 · 一次改动的传播链（讲「为什么不能随便改」）¶

    改一个类（B0-02）
  → 影响所有实例的未覆盖默认值（B0-03）
  → 影响所有 Cast 到它的地方（B4-03）
  → 影响所有引用它的资产（B7-08）
  → 影响 Cook 是否包含它（B8-04）
  → 影响打包体积与加载时间（B8-01）

    对应知识点：B0-02/03、B4-03、B7-08/09/12、B8-04。

    讲项目时：拿「把 50 个交互点合并成 1 个模板」当案例——为什么必须分批、为什么先 Reference Viewer、为什么每批要回归。

    三条线的收口¶

    写项目逻辑时，每一页都问一遍：这页讲的是哪条线的一段？ - 讲不清属于哪条线 → 这页是「知识点堆砌」，不是「项目逻辑」 - 三条线都走通了 → 你已经能对着白板讲完整个项目

    五、条目卡模板（写正文用，比六段式更轻）¶

    ### B4-03 Cast 的代价

**一句话**：Cast 是运行时类型检查 + 强转，成功才继续，失败静默什么都不发生。

**它解决什么问题**：拿到具体类型的引用，才能调它的函数和变量。

**关键点**
- 失败不报错，所以「没反应」类 bug 先怀疑 Cast
- 目标类改名/删除，Cast 节点会变成错误节点，但引用不会自动断
- 大量 Cast 出现在同一个图里 = 结构问题，不是写法问题

**边界**：Cast 不能跨不相关的类；接口调用不需要 Cast。

**关系**：上游是「对象引用」（B4-01），下游是「接口分发」（B4-04）的替代方案。

**本项目**：`BP_ThirdPersonCharacter` 里对交互点的处理（★ 待确认是 Cast 还是接口消息）。

**常见误解**：「Cast 失败会打印警告」——不会，除非你手动加 IsValid。

**自测**：如果 Cast 的目标类被删掉，蓝图会怎样？打包时呢？
