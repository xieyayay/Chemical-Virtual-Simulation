## 三、图怎么维护

图是**手写 HTML**，没有外部依赖（不用 mermaid、不用 CDN），数据全在文件底部的 `VIEWS` 对象里：

```javascript
const VIEWS = {
  arch: { w, h, bands: [...], nodes: [{id,x,y,w,h,t,s,kind,d,doc}], edges: [[a,b],...] },
  boot: {...},
  interact: {...}
};
```

改图 = 改坐标和文字，不需要懂前端。三条规矩：

1. `kind` 只有四种：`core`（框架核心，蓝）/ `debt`（技术债，红）/ `data`（数据层，绿）/ `ui`（界面，黄）
2. 每个节点必须写 `d`（一句话说明）和 `doc`（对应文档路径），否则点了没东西看
3. 新增节点先给坐标，**不要重叠**——重叠时后画的会盖住先画的

## 四、什么时候该换成专业图

手写 SVG 适合「结构稳定、节点 < 30」的图。出现下面任一情况，改用 Archify 生成（本机已装，产出独立 HTML，可导出 SVG/PNG）：

- 节点超过 40 个
- 需要自动避让连线（手写会打结）
- 需要序列图（参与者 × 消息 × 返回）
- 需要 ERD（数据表字段级）

用法（工作目录随便选，产出独立 HTML）：

```text
node "C:\Users\Administrator\.dsh\profiles\web\node_modules\@tt-a1i\archify-dsh\skills\archify\bin\archify.mjs" finalize architecture <candidate.json> <output.html> --quality showcase --json
```
